# 玄鑑 XUAN JIAN

一個**離線可用的命理 PWA**。曆法、節氣、農曆、四柱、星盤、紫微、大運流年、合盤、
易經、塔羅、求籤、姓名五格、數字磁場 —— 全部在你的裝置上算，不連網、不上傳。

需要「解讀」的部分不內建模型，而是幫你把資料組成一段提示詞，
你複製到任何 LLM，再把回覆貼回來存檔。

**線上版**：https://hikari5014.github.io/fortune-telling/

> 零建置、零相依套件。原生 ES Modules + CSS，開一個靜態伺服器就能跑。

## 技術重點

### 命理演算

- **天文**：太陽視黃經（誤差 < 0.01°）、月亮主要項（< 0.3°）、Meeus 朔望公式、ΔT 修正
- **農曆**：定朔定氣法 —— 朔日為初一、無中氣置閏，不依賴任何查表資料
- **上升**：`Asc = atan2(cos RAMC, −(sin RAMC · cos ε + tan φ · sin ε))`，需出生地經緯度
- **行星**：JPL 克卜勒軌道根數解克卜勒方程 → 日心 → 地心 → 加歲差化到當日黃道
- **日柱**：`(JDN + 49) mod 60`
- **大運起運**：順逆依陽男陰女，出生到交節的天數三日折一年
- **易經**：六十四卦由上下經卦查表，動爻變出之卦，另求互卦、錯卦、綜卦
- **筆畫**：由 Unihan 的 `kRSUnicode`（部首序號 + 餘筆）推算康熙筆畫
- **建除**：日支與月建相同者為「建」依序而下，節後換月建（交節前後會連兩天同神，與通書一致）
- **八宅**：遊年卦變由爻象推導 —— 上爻變生氣、中下爻變天醫、三爻全變延年、中爻變絕命…不查表

### 分享長圖

用 canvas 自己排版，沒有加任何套件。兩次走訪：第一次只量高度、第二次才真的畫，
所以圖高剛好貼合內容。中文沒有空格可以斷行，所以逐字量寬，並處理兩條禁則 ——
行首不可以是「，。、）」」，行末不可以是「（《「」。輸出跟著目前主題，深色模式出深色卡。

手機上優先呼叫系統分享（`navigator.share` 帶檔案），不支援時退回下載 PNG。

### 介面與動態

- **黑白主題**：純單色設計代幣系統，層次靠灰階、細線與留白
- **圖示**：30 個自繪 SVG，滑過時線條加粗（等同字重變化）並依語意「演一下」自己的意思
  —— 設定轉 60°、重新整理逆轉 120°、箭頭前進 4px、上傳往上、下載往下
- **過場**：只有主內容區參與 View Transition，固定的側欄與吸頂列不跟著位移；
  `scrollbar-gutter: stable` 讓捲軸寬度恆定，切到較短的頁面不會左右跳
- **手勢**：滑動切頁有方向鎖定、rAF 節流、慣性捲動保護、螢幕邊緣讓位
- **抽屜**：class 驅動的 transition（不是 animation），拖曳與關閉都能接手
- **動畫強度**：設定可切「關閉／輕量／完整」，並尊重 `prefers-reduced-motion`
- **命盤特效**：星盤的相位連線、星體光暈、刻度環自轉；紫微的宮格浮現與三方四正描邊。
  光暈用低透明度描邊而不是 SVG 濾鏡（濾鏡在手機上很貴），而且特效不改變任何位置與數字
- **分數色階**：0 紅 → 100 綠。顏色是第三個管道 —— 弧長與中央數字本來就各自表達一次分數，
  所以紅綠色盲照樣讀得到。八字旺衰刻意不套，因為那裡 100 分不等於「好」

### iOS 專門處理

這些都是實機上看得到差別的：

- 用 `svh` 取代 `dvh`：Safari 網址列收合時 `dvh` 會持續變動，版面每幀改變尺寸
- 固定層不使用 `mix-blend-mode`：會強制整頁每一幀重新混色
- 觸控裝置停用 `backdrop-filter` 與指標光暈，改用獨立合成層
- 鎖背景捲動不改動版面（擋 `touchmove`，不是 `position: fixed`），網址列不會突然展開
- 可編輯欄位字級不低於 16px，聚焦時不會自動放大整頁
- 以 `visualViewport` 追蹤鍵盤高度，抽屜自動讓開

### PWA

Service Worker 快取應用程式外殼與 Google Fonts，完全離線可用。
新版本接管後自動重新載入，「關於」頁可手動檢查更新。

## 資料來源與準確度

### 籤詩

內建的「玄鑑六十籤」是**本專案自撰**的七言四句，依六十甲子編號，
**不是任何宮廟籤詩的原文**。傳統的六十甲子籤、觀音百籤版本眾多，
憑記憶寫出來容易變成假的經文，比不做更糟，所以選擇自撰並在介面與文件明確標示。

想用自己常去的宮廟籤詩：

1. 求籤頁「管理籤詩集」貼上 JSON 匯入（格式在同一個對話框裡，可一鍵複製）
2. 用內建的「查籤詩原文」提示詞請外部 LLM 提供，該模板明確要求
   **沒有把握的籤必須留空、不准自行創作**，再把結果貼回來匯入

### 塔羅

**牌圖**是 Rider–Waite–Smith（1909）的公有領域掃描，取自 Wikimedia Commons，
由 `tools/fetch_tarot.py` 轉成灰階、280px 寬的 WebP（78 張約 2.3 MB）。
繪者 Pamela Colman Smith 卒於 1951 年，美國、歐盟與台灣均已過保護期；
授權細節與「U.S. Games Systems 的商標與重製版另有權利」這件事寫在
`assets/tarot/CREDITS.md`。

牌圖**不進安裝時的外殼快取** —— 第一次看到哪張才下載哪張，
存在跟版號無關的 `xj-tarot` 快取，換版本不會重抓。設定頁可以整個關掉。

**牌義**（關鍵字、核心課題、數字階段、宮廷角色）是**本專案自撰整理**。
塔羅沒有單一權威版本：偉特自己的《The Pictorial Key to the Tarot》（1911）很簡略，
之後一百年各家各講，所以這裡標示清楚是自撰，不冒充古本。

**占星對應**則有明確系統來源（黃金黎明），而且是推得出來的：

- 大牌 22 張對應 10 顆行星與 12 星座，各一次不重複
- 小牌 2–10 對應黃道三十六旬 —— 從牡羊 0° 起每 10 度一旬，
  花色跟著星座元素走（火→權杖、土→錢幣、風→寶劍、水→聖杯），
  數字三個一組（2,3,4 / 5,6,7 / 8,9,10），行星按迦勒底順序接排。
  4 與 3 互質，十二星座剛好把 36 張牌不重不漏排完 —— 所以程式直接算，不放查表。

有了這層對應，就能把牌面接回你自己的本命盤：抽到高塔就去看你的火星在第幾宮，
抽到錢幣八就去看有沒有星體落在處女座 0°–10°。這是塔羅頁少數真的在「算」的東西。

**本命牌**（月＋日＋西元年收斂到 1–22）是二十世紀才成形的做法，沒有古籍出處，
介面上照實標明，跟八字、紫微的地位不一樣。

**今日一張**用「日期＋這個人的識別碼」當種子，同一天重新整理不會換牌。

**抽牌儀式**（`src/tarotdraw.js` + `src/starfield.js`）是一支全螢幕過場：
聚牌 → 洗牌 → 攤成七十八張的扇形 → 手指滑過去挑 → 選滿自動翻開 → 進解說。

- **牌在洗好的那一刻就定了**，你挑的是位置 —— 跟實體牌一樣，不是等你點完才決定給你哪張
- 牌背（`assets/tarot/back.webp`）補過左右邊，跟牌面調成同一個比例；
  兩面尺寸不一樣的話翻牌會抽動
- 正面的圖等那張被挑走才載 —— 七十八張一次載是 2 MB，而且九成七不會被翻開
- 這一頁永遠是暗的，不跟隨淺色主題
- 動畫強度關閉、或系統要求減少動態時整段跳過（不是播快一點）

### 筆畫字典

由 Unicode Unihan 的 `kRSUnicode`（部首序號 + 餘筆）推算，**涵蓋 CJK 基本區全部 20,992 個漢字**。
康熙筆畫 = 部首本身的筆畫 + 餘筆，這正是姓名學所用的計法，所以氵自動算 4、艹算 6、
阝左算 8 右算 7，不需要另外維護對照表。

- 產生腳本：`tools/gen_kangxi.py`（讀 Unicode 官方 `Unihan.zip`）
- 少數姓名學慣用值與推算不同的字（蕭 19、萬 15、泰 10…）列在 `EXCEPTIONS` 例外表
- 數目字一～十可選擇「依數值計」或「依康熙實際筆畫」（設定頁切換）
- 仍有疑義的字可在姓名頁手動修正，或用內建的「查康熙筆畫」模板去問外部 LLM

### 擇日

採**建除十二神**這一派，加上彭祖百忌與沖煞。評分基準 60 分起算，
每一筆加減都連同來源標籤列在畫面上，不做看不懂的黑箱分數。

刻意不做的有兩類：二十八宿需要歷史紀元錨點，各家錨點不同；
通書裡數十種吉神凶煞（天德、月德、受死、往亡…）各派取用不一，
同一天在不同通書上可能吉凶相反。這些留給「擇日評估」模板去問外部 LLM，
並要求它標明是哪一派的說法。

### 行星

行星位置用 JPL「Approximate Positions of the Planets」的克卜勒軌道根數（適用 1800–2050），
解克卜勒方程得日心座標，減地球日心座標成地心座標，再加歲差化到當日的黃道（占星用的回歸黃道）。

驗證方式是**兩套完全獨立的演算法互相對照**：用行星這條鏈路把「地球日心位置 + 180°」
算成太陽的地心黃經，跟 `calendar.js` 那套 Meeus 太陽視黃經公式比 ——
1900–2050 年間最大差 **0.61 角分**，而且這個差正好是光行差（20.5″）加章動（≤17″）的量級，
表示克卜勒解算、座標轉換與歲差項全都對。

另外四項結構性檢驗也都符合公認值：

| 檢驗 | 算出來 | 公認值 |
|---|---|---|
| 水星最大距角 | 27.8° | ~28° |
| 金星最大距角 | 47.2° | ~47° |
| 火星逆行 | 76 天／次 | 60–80 天 |
| 土星逆行 | 139 天／次 | ~140 天 |

### 方位

八宅的八個方位不是查表，是**一爻一爻變出來的**：本命卦與方位卦比對哪幾爻不同，
上爻變是生氣、中下爻變是天醫、三爻全變是延年、中爻變是絕命，以此類推。

因為是推導，所以可以用結構性質自我驗證，這三項都通過：

1. **對稱性** —— 乾命的兌方是生氣，兌命的乾方也必須是生氣（64 格全對）
2. **不重不漏** —— 每個命卦的八個方位剛好蓋到八顆星各一次
3. **東西四命** —— 四個吉方必定落在同組的四個卦上（這是東四／西四命的定義，
   而它是從爻變規則自然長出來的，不是寫死的）

本命卦用「西元年各位數相加 → 男 11 減、女 4 加」的算法，四位數全用到，
所以跨世紀不需要換公式（常見的「100 減年份後兩位」在 2000 年後會算錯）。

### 提示詞產生器

設計原則是**夠自由**：

- **聚焦項目** —— 在紫微點某一宮、在星盤點某顆星、在方位點某一方，
  抽屜裡的「深問這一項」會把那一項的完整資料帶到提示詞頁，
  插在「輸出要求」之前，當成這次回答的主軸
- **自訂變數** —— 自己定義 `{{名稱}}`，模板裡跟內建變數一樣用
- **輸出控制可以自己打字** —— 語氣不限於預設那幾種，想要「像武俠小說的說書人」就直接打
- **額外指示** —— 一個萬用欄位，內容直接接在最後
- **預覽直接改** —— 最終文字可以手動編輯，複製的就是改過的版本

### 語調：白話與文言

App 自己寫的解釋文字有兩套，設定頁可切。文言版**範圍是有界的**，只收
建除十二神、黃黑道十二神、八宅八星、數字八星磁場、生命靈數、西洋十二宮，共 76 條。

塔羅牌義與易經卦爻**刻意不做文言版**：前者本來就是關鍵字不是散文，
後者應該引用《周易》原文，由本 App 改寫成文言只會變成假的經文。

語調由引擎的 `reg` 參數決定，引擎不直接讀設定，維持純函式好測試。
提示詞也會跟著加一條輸出要求，讓 LLM 用同一種口吻回答。

### 八字旺衰

採用**扶抑為主**這一派：先判日主強弱，強則喜洩耗、弱則喜生扶。
評分拆成得令、得地、得助、洩剋四類，每一筆加減都列在畫面上。

**不內建**的部分：從格、化格、專旺格，以及《窮通寶鑑》的調候用神（10 干 × 12 月共 120 條）。
這些各家取用差異極大，憑記憶寫出來就是假的。改由提示詞請外部 LLM 引用原典並標明流派 ——
跟籤詩、爻辭是同一條線。

能推導的照樣自己算：寒暖燥濕由月支與火水多寡判斷，是原理層面的東西，不是查表。

### 流派差異

命理各家算法不同。本專案在有分歧的地方一律**明講採用哪一種、並盡量做成可切換**：
早晚子時換日、姓名學外格規則、數目字筆畫、擲筊確認次數，都在設定頁或頁面上可調。

## 原型（lab/）

`lab/` 放的是還沒決定要不要做的互動原型，**不屬於 App 本體**，
也不在 Service Worker 的外殼清單裡，只是跟著網站一起部署，方便在手機上試玩。

### `lab/nav.html` — 導覽改造

功能超過十五個之後，平鋪的清單就不好找了。原型現在長這樣：

- **分類列排成扇形**：中間最高、兩端往下沉，按鈕跟著微微外傾。
  弧度用「第幾個換算成 −1..1 再取平方」算，不量容器寬度，所以轉螢幕、換字級都自己跟上。
- **首頁卡在扇形正中央下面的凹處**，做成圓形 —— 它不是分類而是一顆「回到原點」的鍵，
  形狀不一樣才一眼分得出來。拇指最好按的位置留給最常按的東西。
- **四個分類**：工具（最左）、命盤、占卜、人際。
  擇日與方位併進占卜；合盤、面談、姓名、數字併成人際。
  四個是偶數，扇形頂端是平的，圓形的首頁鍵剛好卡在那個凹口。
- **點一下叫出停住的選單**，再點一下要的那一項；也可以按著滑過去再放開。
  **沒有長按** —— 長按每次都要先等三百毫秒，而且對手指不方便的人不友善。
- 細項用**滑選清單**呈現。輪盤與拇指扇兩種排法留著對照，操作方式完全一樣。

幾何的部分有測試守著（`tests/lab-nav.test.js`）：不管從哪裡按、幾個項目、
什麼螢幕尺寸，每一項都要畫在畫面裡、彼此不能疊住，而且
**指著哪一項就一定要選到哪一項**；扇形要左右對稱、中間最高。

這一版的結論已經套進 App 本體（v0.19.0），原型留著當紀錄。

## 開發

### 改版流程

1. 改 `src/data/changelog.js` 的 `APP_VERSION`，並在 `CHANGELOG` 最前面加一筆
2. 把 `sw.js` 的 `VERSION` 改成同一組版號
3. `python3 tools/check_version.py` 確認一致（CI 在部署前也會跑）

### 重新產生資料

```bash
# 康熙筆畫字典（需要 Unicode 官方 Unihan.zip）
curl -sSLO https://www.unicode.org/Public/UCD/latest/ucd/Unihan.zip
python3 tools/gen_kangxi.py Unihan.zip src/data/kangxi.js

# App 圖示 PNG
python3 tools/make_icons.py
```

### 測試

```bash
node --test --test-reporter=spec tests/*.test.js
```

零相依，用 Node 內建的 `node:test`，不需要 npm install。CI 在每次推送與 PR 時跑，
部署前再跑一次，沒過就不上線。198 個測試涵蓋十一個引擎、提示詞組裝與全部 18 個頁面的繪製。

細節見 `tests/README.md`。幾個比較有意思的：

- **交叉驗證**：行星鏈路反推的太陽黃經，必須與獨立的 Meeus 公式吻合到角分以內
- **結構性質**：八宅遊年的對稱性、八星不重不漏、東西四命分組（這是定義，不是寫死的）
- **對照公認值**：水金最大距角、火土逆行天數
- **模組載入**：`node --check` 攔不住重複匯出，只有真的 `import()` 會發現

### 沒有建置步驟

不需要 npm、不需要打包。改完檔案重新整理瀏覽器就好。
唯一要注意的是 Service Worker 會快取舊檔 —— 開發時在 DevTools 勾選 *Bypass for network*。

## 部署到 GitHub Pages

專案已附上 `.github/workflows/deploy.yml`，推送 `main` 後自動部署。

第一次設定（只要做一次，**必須手動**）：

1. 到 repo 的 **Settings → Pages**
2. **Build and deployment → Source** 選 **GitHub Actions**
3. 回到 **Actions → Deploy to GitHub Pages**，按 **Run workflow** 重跑一次

> 為什麼不能自動？Actions 的預設 `GITHUB_TOKEN` 沒有建立 Pages 站台的權限，
> 會回 `Resource not accessible by integration`。啟用之後每次推送都會自動部署。

注意事項：

- 站台部署在子路徑底下，所以所有路徑都必須是**相對路徑**（本專案已全部使用相對路徑）
- `.nojekyll` 一定要保留，否則 Jekyll 會忽略 `src/views/_shared.js`（底線開頭的檔案）
- 若出現 `Branch is not allowed to deploy to github-pages`，表示 `github-pages`
  環境限制只能從預設分支部署，把分支合併到 `main` 即可
